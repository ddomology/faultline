# 풀이를 기록하는 방법

문제 목록에서 **노트 작성**을 누르면 문제 제목과 원문 링크가 입력된 초안이 열립니다.

## 사이트에서 시작하기

1. 첫 화면에서 전체 문제를 보거나 검색·주제·난이도로 좁힙니다.
2. **노트 작성**을 누르고 목표, 시도, 결과를 기록합니다.
3. 초안은 현재 브라우저에 임시 저장됩니다. 다른 기기와 자동으로 동기화되지는 않습니다.
4. **GitHub에 저장**을 누르면 파일 생성 화면이 열립니다. GitHub에서 내용을 확인하고 **Commit changes**까지 완료합니다.
5. 배포가 끝나면 문제 목록에 **풀이 읽기**가 나타납니다.

**노트 모아보기**에서는 문제와 연결하지 않은 개념 정리까지 함께 읽을 수 있습니다. 노트 상단의 **전체 문제**를 누르면 목록으로 돌아갑니다.

이미 저장소에 있는 노트는 GitHub의 **편집** 화면에서 수정합니다. GitHub는 저장소 쓰기 권한이 있는 사람만 변경할 수 있습니다.

## 옵시디언에서 작성하기

저장소를 PC에 복제한 뒤 `content` 폴더를 옵시디언 보관함으로 엽니다.
사이트에서 내려받은 Markdown 파일을 안내된 `labs/주제/파일명.md` 경로에 넣거나, `templates/lab.md`를 복사해 사용합니다.

노트 상단의 `lab_url`에 문제의 원문 URL을 넣으면 파일명이나 위치를 바꾸어도 문제와 연결됩니다.

```yaml
---
title: 내 풀이 제목
lab_url: https://portswigger.net/web-security/주제/lab-문제명
tags:
  - portswigger
draft: false
---
```

`draft: true`는 웹사이트에서 제외합니다. 완성한 노트는 `draft: false`로 바꾸고 commit/push합니다.
옵시디언에서 파일만 저장하면 GitHub에는 아직 반영되지 않습니다. Git으로 전송하거나 Obsidian Git 자동 동기화를 설정해야 합니다.

## 이미지와 노트 연결

이미지를 `content/attachments`에 저장하고 `![[attachments/파일명.png]]`로 넣을 수 있습니다.
관련 개념은 `[[노트 이름]]`으로 연결합니다. 같은 이름의 파일이 여러 개라면 `[[폴더/노트 이름]]`처럼 보관함 안의 경로를 함께 적습니다.
쿼리는 `sql`, PowerShell은 `powershell` 코드 블록에 작성합니다. 표, `> [!note]` 콜아웃, 수식도 웹 본문에 렌더링됩니다.

## 풀이 상태의 의미

완료 상태는 2026년 9월 29일 저장한 PortSwigger 문제 목록의 스냅샷입니다. PortSwigger 계정에 실시간으로 연결되지는 않습니다.
사이트의 노트 유무는 배포할 때 저장소 내용을 기준으로 갱신됩니다. 즐겨찾기와 작성 중 초안은 현재 브라우저에만 저장됩니다.

이 저장소는 공개이므로 `draft: true`인 파일도 GitHub에서는 보입니다. 세션 쿠키·토큰·API 키를 풀이에 붙여 넣지 마세요.
