## 4회차 구현

- 273개 기존 `.html`과 확장자 없는 노트 주소를 보존하고, 폴더·태그·목록·작성 안내 101개 별칭을 연결했습니다. 원본 Markdown·첨부는 수정하지 않습니다.
- 각 페이지의 canonical·설명·공유 카드·JSON-LD, 274개 URL의 사이트맵, 작성된 글 RSS를 생성합니다. 404는 실제 404 상태의 독립된 정적 문서로, 알 수 없는 경로에서 중복 초기화되지 않습니다.
- 현재와 직전 두 배포의 해시 에셋을 유지합니다. 이전 파일은 크기·SHA-256으로 검증하며 보존에 실패하면 배포를 중단합니다. Quartz의 CSS와 한 번만 새 문서로 이동하는 호환 스크립트도 남깁니다.
- 이동 데이터의 배포 버전이 다르면 목적 주소를 유지하고 문서를 다시 엽니다. 연결 실패에는 Explorer를 유지하는 재시도 화면을 제공합니다. 저장된 테마는 앱 스크립트보다 먼저 적용합니다.
- 운영 워크플로는 React 출력과 30일짜리 배포 스냅샷을 만듭니다. 수동 `Restore Quartz baseline`은 전환 직전 커밋을 재현합니다. 복구 방법과 한계는 [관리 문서](maintaining.md#복구)에 있습니다.
- WebKit에서 긴 목록을 새로고침할 때 초기 24개 행의 높이에 스크롤이 잘리는 문제를 수정했습니다. 저장 위치에 필요한 높이를 잠시 확보하고 목록·폰트 준비 후 해제하며, 스크롤 자체는 React Router가 관리합니다.
- PR 검사를 모든 변경에 실행하며 Chromium PC·Android와 WebKit iPhone 에뮬레이션을 검사합니다. 실제 휴대폰의 OS 앱 전환·메모리 회수·주소 표시줄 동작은 에뮬레이션과 구분합니다.

## 3회차 구현

- 기존 `site/code-format.ts`와 `site/code-highlight.ts`를 공통 빌드 엔진으로 사용합니다. 루트 의존성을 CI에도 설치하며 `_quartz`의 생성 파일에 의존하지 않습니다.
- 원문/정렬 보기·정확한 문자열 복사·복사 실패 피드백·긴 줄 줄바꿈을 React로 구현했습니다. 조각·잘못된 문법·모르는 언어·작성자의 opt-out은 원문을 유지합니다. 줄/단어 강조가 있으면 원문을 먼저 보여 줍니다.
- 콜아웃과 네이티브 접기, 위키링크·이미지 임베드, KaTeX 수식, 각주 왕복 링크를 렌더링합니다. 원문 HTML을 먼저 제한하고 빌드에서 생성한 강조·수식만 이후에 추가합니다.
- 표의 독립 가로 스크롤과 키보드 접근, 이미지 고유 크기·설명·확대 다이얼로그를 연결했습니다. 확대를 닫거나 글이 바뀌면 스크롤 잠금과 포커스를 정리합니다.
- 접을 수 있는 목차·한글 제목 링크·같은 주제의 이전/다음 글·Markdown 원문 링크를 추가했습니다. 글 사이를 이동해도 Explorer와 목록 복귀 조건을 유지합니다.
- `dangerouslySetInnerHTML`로 본문을 통째로 교체하는 대신, 빌드에서 검증한 HAST를 React 컴포넌트로 렌더링합니다. SSR과 클라이언트가 같은 본문을 사용하며 기존 Quartz의 DOM 후처리 스크립트는 실행하지 않습니다.
- 320px 화면에서 코드 도구막대가 hydration 전 42px에서 후 45–51px로 바뀌는 것을 측정했습니다. 버튼·줄바꿈 슬롯·복사 피드백 너비를 처음부터 확보했고, JavaScript를 지연시킨 검사에서 전후 높이가 같습니다.

공개 글에서 사용하지 않는 Mermaid 도표와 다른 노트 본문의 전체 삽입은 보류합니다. 코드/링크를 읽을 수 있게 남기며 manifest에 기록합니다. 현재 원문 273개와 첨부 14개의 바이트는 유지했습니다.

## 2회차 구현 기록

### 목록과 검색

- 풀이/개념 목록, 검색어·주제·난이도·정렬 조건을 URL의 `view/q/topic/level/sort`로 표현합니다.
- 한국어·영문 제목, Explorer 제목, 번호, 기존 본문의 읽을 수 있는 텍스트를 검색합니다. 실습 예제는 실행하지 않습니다.
- 기본 24개를 표시하고 `limit`으로 더 보기 개수를 보존합니다. 글을 읽은 뒤 뒤로 가면 같은 조건과 목록 길이를 사용합니다.
- 최근 수정일은 Git의 실제 콘텐츠 변경 이력을 사용합니다. 원문 `updated`/`modified`가 있으면 우선하며, 근거가 없으면 날짜를 만들지 않습니다. CI는 전체 Git 이력을 가져옵니다.
- 헤더 검색은 Ctrl/⌘ K로 이동하며, 한글 조합 중 제출을 막고 브라우저 뒤로/앞으로와 입력 값을 맞춥니다.

### 화면 상태와 스크롤

- 헤더·Explorer는 공통 React 레이아웃에 유지합니다. 폴더 확장과 Explorer 위치는 풀이/개념별로 보존합니다.
- 닫힌 주제의 전체 노트 링크는 DOM에 만들지 않습니다. 서버 HTML에는 현재 글의 주제를 펼칩니다.
- 문서 스크롤은 React Router `ScrollRestoration` 한 곳에서 관리합니다. 필터와 더 보기는 `preventScrollReset`을 사용합니다.
- 모바일 메뉴는 목적지 이동이 완료된 뒤 닫습니다. Escape와 화면 너비 변경도 처리하고, 본문 포커스 이동에 `preventScroll`을 적용합니다.
- 창 전환·resize·이미지 지연 로딩을 이유로 나중에 문서 스크롤을 강제로 되돌리는 별도 보정은 넣지 않습니다.
- 모바일 에뮬레이션에서 초기 한글 폰트 적용 후 브라우저 scroll anchoring이 저장 위치를 185px 옮기는 현상을 확인했습니다. 첫 hydration과 폰트 적용이 끝날 때까지만 anchoring을 억제하고 다시 허용합니다. 별도 `scrollTo`는 호출하지 않으며, JavaScript가 꺼져 있으면 이 억제도 적용하지 않습니다.
- 글의 목록 복귀 링크는 최근 목록의 검색 조건과 표시 개수를 유지합니다.

### 출력과 데이터

1. 기존 `content/`의 273개 노트와 14개 첨부를 읽습니다. 원문은 변경하지 않습니다.
2. React 19.3.0, TypeScript 7.0.2, React Router 8.4.0, Vite 8.3.1로 정적 HTML과 이동용 `.data`를 만듭니다.
3. 전체 목록 메타데이터는 한 번 받는 공통 JS 모듈로 옮겼습니다. 각 페이지의 root loader에는 브랜드와 배포 주소만 남깁니다. 전체 글 HTML은 서버 빌드 입력으로 유지합니다.
4. 기존 `.html` 주소는 실제 파일입니다. 확장자 없는 주소에는 작은 이동 페이지를 생성해 검색 문자열·한글 fragment를 유지하며 정규 주소로 이동합니다. 같은 글의 전체 HTML/데이터를 두 번 빌드하지 않습니다.
5. 엄격한 정적 서버로 검사합니다. 없는 주소를 홈으로 바꾸는 SPA fallback을 사용하지 않습니다.

1회차 정적 출력은 약 294 MB였으며, 같은 카탈로그와 전체 별칭 페이지의 중복이 원인이었습니다. 2회차 기본 경로의 정적 출력은 약 20.1 MB로 줄었습니다(약 93% 감소). 대표 글 HTML도 약 354 KB에서 67.7 KB로 줄었습니다. 이는 배포 파일 측정이며 실제 휴대폰의 로딩 성능 평가와 구분합니다. 현재 검색용 본문 텍스트도 공통 목록 모듈에 포함되므로 글이 크게 늘면 검색 인덱스의 별도 지연 로딩을 검토할 수 있습니다.

## 남은 회차

### 운영 전환 이후

실제 Android·iOS에서 탐색창을 연 상태로 다른 앱에 갔다 돌아오고, 글 이동·뒤로 가기·화면 회전 후 터치 스크롤을 확인할 수 있습니다. 자동 검사는 visibility 이벤트·뷰포트 전환·스크롤 잠금 해제를 포함하지만 OS의 실제 탭 정지까지 재현하지 않습니다.

Mermaid 도표, 다른 노트 본문 전체 삽입은 기존에 기록한 미지원 범위입니다. 이전 단계의 수치는 당시 측정치이며 현재 상태는 4회차 기록과 CI를 따릅니다.
